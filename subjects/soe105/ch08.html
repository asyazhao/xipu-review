数组：查找与排序

Arrays: Searching & Sorting

来源 L09 · 术语 8 个

虚线下划线为术语；悬停查看中文、英文与释义，完整词典见“术语”。

本章把“在数组里找一个值”和“把数组排好序”这两件事拆成可执行的算法：三种查找（无序线性、有序线性、二分）与两种排序（选择、冒泡），重点是循环条件与边界怎么写。

本章要点

  • 无序线性查找从头扫到尾；不加 break 时，重复元素会留下最后一次出现的下标。
  • 有序线性查找可以提前退出：循环条件要加上 A[n] <= x。
  • 二分查找每次排除一半区间，只能用于有序数组，用 lower、upper、middle 三个变量维护边界。
  • 排序既是独立需求（名单、成绩、名次），也是二分查找的前置准备。
  • 选择排序每轮把未排序部分的最大值换到末尾，未排序部分从右往左收缩。
  • 冒泡排序每轮比较相邻元素并交换逆序对，最大值“冒”到未排序部分的末尾。

8.1 无序线性查找：问题与第一版实现

查找任务的定义很朴素：在一个无序数组unordered array中找出某个值 x，找到就保存它的下标，找不到就把下标置为 −1。讲义把这个任务拆成三件事：输入是整数列表、列表中整数的个数、待查找的值 x；输出是找到时的下标或 −1；约束是查找过程不改变列表本身。

线性查找linear search的做法是从第一个元素开始，逐个与 x 比较。讲义先给出一个“初步设计”（preliminary design）：先假设值不在数组中，把 index 置为 −1；从第一个元素开始；只要数组中还有元素，就检查当前下标的元素是否等于 x，相等则保存下标，然后看下一个元素；最后输出结果。

把这个设计直译成代码，就是下面这段程序。注意它没有在找到之后停下来：

int A[] = {10, 22, 3, 22, 46, 51, 8, 44};
int arraySize = 8;
int x, index;

cout << "Enter search element: ";
cin >> x;

index = -1;
for (int n = 0; n < arraySize; n++)
    if (A[n] == x)
        index = n;

if (index == -1)
    cout << "Element NOT found!" << endl;
else
    cout << "Element at index: " << index << endl;

讲义在幻灯片上直接问：这段代码“问题在哪里？怎么解决？”。原因在于循环体内只做了“记录下标”，没有做“停止查找”。当数组里有重复值时（例子里 22 出现了两次），后面的元素会覆盖前面记录的下标，最后留下的是最后一次出现的位置；同时，已经找到答案之后剩下的比较都是白做的。

考点

无序线性查找的返回值语义是“找到的下标，否则 −1”。判断是否找到，看的是 index 是否仍为初值 −1，而不是看循环变量 n 的终值。

8.2 用 break 收束查找

改进后的算法只多加了一步：在“保存下标”之后“退出循环”（exit the loop）。讲义把这个“退出”落实到 C/C++ 的 breakbreak statement 语句上，其余部分一字未动。这样，第一个匹配的元素就决定了结果，重复值不再造成覆盖，后续比较也被省掉。

index = -1;
for (int n = 0; n < arraySize; n++)
    if (A[n] == x) {
        index = n;
        break;
    }

把两版代码放在一起看，可以提炼出一条通用的读代码方法：先问“循环什么时候结束”，再问“结束时哪些变量已经被写过”。第一版的循环只在 n 走到 arraySize 时结束，index 可能被写多次；第二版的循环有两个出口——找到（break）或走完（n 越界），而 index 一旦被写就不会再改。

易错

不要用“循环结束后 n 的值”去反推是否找到：break 退出时 n 停在匹配位置，正常结束时 n 等于 arraySize，两种情况都可能让 n 落在合法范围内，只有 index 才是可靠的结果变量。

L9 p.5–6

8.3 有序线性查找：多一个条件就能提前收工

如果数组本身已经排好序，线性查找就不必扫完整个数组。讲义用的例子是 {1, 7, 9, 10, 12, 14, 23, 40}：一旦扫描越过了“值可能出现的位置”，后面只可能更大，继续找没有意义，可以直接退出。

落实到代码上，这个“提前退出”体现为 for 循环的第二个条件：有序线性查找ordered linear search在 n < arraySize 之外再加一条 A[n] <= x。当前元素大于 x 时，循环条件先失效，循环自然结束，index 保持 −1。

int A[] = {3, 8, 10, 22, 22, 44, 46, 51};
int arraySize = 8;
int x, index;

cout << "Enter search element: ";
cin >> x;

index = -1;
for (int n = 0; n < arraySize && A[n] <= x; n++)
    if (A[n] == x) {
        index = n;
        break;
    }

这里有一个很容易写错的细节：条件必须是 A[n] <= x，不能写成 A[n] < x。写成就小于，遇到“正好等于 x”的元素时循环条件先不成立，循环在检查相等之前就结束了，明明存在的值会被判成找不到。

考点

有序线性查找的两个出口：A[n] == x 时 break（找到），A[n] > x 时循环条件失效（不可能再找到）。两种情况都靠最后的 index 判断区分。

L9 p.6–8

8.4 二分查找：每次砍掉一半

二分查找binary search的核心思想与中学学过的二分法一致，讲义把它归入分治divide-and-conquer策略：先看数组的中间元素，然后只保留“答案可能在”的那一半。

  • 如果值就在中间元素上，过程结束。
  • 如果中间元素的值小于待查找的值，排除数组的前一半。
  • 如果中间元素的值大于待查找的值，排除数组的后一半。
  • 重复上述过程，直到找到元素，或者整个数组都被排除。

讲义特别强调了一句前提：二分查找只能作用于有序（已排序）的列表。原因藏在“排除一半”这个动作里——只有数组有序时，才能由“中间元素比 x 小”推出“左半部分全都比 x 小”，否则被排除的那一半里可能正好藏着答案。

“砍一半”带来的直接后果是比较次数：线性查找最坏要看完全部 n 个元素，二分查找每比较一次区间长度就减半。讲义没有展开复杂度记法，但这个差别在实现里是可以数出来的。

L9 p.9–10

8.5 二分查找的实现与边界维护

实现二分查找需要三个变量：下界 lower、上界 upper 和中间位置 middle。初始时 lower = 0，upper = arraySize − 1，middle = (lower + upper) / 2。循环条件写成一个合取式：中间元素不等于 x，并且区间还没有缩成一个点。

int lower = 0;
int upper = arraySize - 1;
int middle = (lower + upper) / 2;

while (A[middle] != x && lower < upper) {
    // check which side to eliminate by updating the boundary
    if (x < A[middle])
        upper = middle - 1;
    else
        lower = middle + 1;
    // update middle value
    middle = (lower + upper) / 2;
}

if (A[middle] != x)
    cout << "Element NOT found!" << endl;
else
    cout << "Element at index: " << middle << endl;

循环体做两件事：先用 x 与 A[middle] 的大小关系决定砍掉哪一边，再把 middle 重算到新区间的中点。砍边界的写法是 middle − 1 与 middle + 1，而不是 middle——A[middle] 刚刚比较过且不相等，它本身也应该被排除，否则区间可能原地不动。

用讲义里的数组 {3, 8, 10, 22, 22, 44, 46, 51} 走两遍。找 44：lower = 0、upper = 7、middle = 3，A[3] = 22 < 44，于是 lower = 4；重算 middle = (4 + 7) / 2 = 5，A[5] = 44，循环结束，输出下标 5。找 5：middle = 3，A[3] = 22 > 5，upper = 2；middle = 1，A[1] = 8 > 5，upper = 0；此时 lower = 0、upper = 0，lower < upper 不成立，循环结束，A[0] = 3 ≠ 5，输出未找到。

易错

把 upper 更新成 middle（或 lower 更新成 middle）会让区间无法继续收缩，区间长度停在 2 时可能反复取到同一个 middle，形成死循环；必须写成 middle − 1 与 middle + 1。

考点

循环结束后不能直接认定找到，必须再用 A[middle] != x 复核一次：lower == upper 时退出，只说明区间缩到一格，这一格仍可能是别的值。

8.6 排序的用途与算法清单

排序sorting是把一组条目按某种指定顺序排成序列。讲义列了四类典型场景：按姓名排列的学生姓名与学号表；按分数排列、准备换算等级的成绩单；按完赛时间排列的赛马名次；以及把一个原本无序的数组整理好，以便使用有序二分查找。

讲义给了一个值得记住的量级判断：全部计算能力中约有 25% 到 50% 花在排序上。它同时给出三个可能的原因——很多应用确实需要排序；很多应用在不必要的时候也做了排序；很多应用用了效率不高的排序算法。这三条其实对应三个不同的改进方向：想清楚要不要排、只排该排的部分、换更合适的算法。

讲义点名的排序算法有：选择排序selection sort、冒泡排序bubble sort、Shell 排序（简单但更快）、快速排序（对多数应用快得多）、基数排序（radix sort）与计数排序（counting sort）。本章只展开前两种，它们是最容易手写、也最容易在纸上推演的两个。

辨析

排序与查找不是并列的两件事：排序常常是查找的准备步骤。二分查找要求有序，而把无序数组变成有序数组，正是排序要解决的问题。

L9 p.12–14

8.7 选择排序：把最大值换到末尾

选择排序的做法是：反复把未排序部分中最大的元素放到这段的末尾，直到整个数组有序。讲义说它“接近很多人手工排序的习惯”——先扫一遍找出最大的，挪到最后，再在剩下的里面找次大的。

算法分四步：把整个数组定义为未排序部分；只要未排序部分非空，就找出它的最大元素，与未排序部分的最后一个元素交换，然后把未排序部分缩小一个位置；最后输出结果。代码用 rightmost 标记未排序部分的右端，从 arraySize − 1 开始一路减到 1。

int maxIndex;
int temp;

for (int rightmost = arraySize - 1; rightmost > 0; rightmost--) {
    // find largest item in the unsorted part
    maxIndex = 0;
    for (int i = 1; i <= rightmost; i++) {
        if (A[i] > A[maxIndex])   // update maxIndex if greater
            maxIndex = i;
    }
    // swap largest item with last item
    temp = A[rightmost];
    A[rightmost] = A[maxIndex];
    A[maxIndex] = temp;
}

内层循环从 i = 1 开始，是因为 maxIndex 已经初始化为 0，第 0 个元素天然是“当前最大值”的候选，不需要再和自己比一次。外层循环用 rightmost > 0 而不是 >= 0，是因为当未排序部分只剩一个元素时，它必然是剩下的最小值，位置已经正确，再处理一次只是空转。

用讲义数组 {10, 22, 3, 22, 46, 51, 8, 44} 走前三轮：rightmost = 7 时最大值为 51（下标 5），与 A[7] = 44 交换，得到 {10, 22, 3, 22, 46, 44, 8, 51}；rightmost = 6 时最大值为 46（下标 4），与 A[6] = 8 交换，得到 {10, 22, 3, 22, 8, 44, 46, 51}；rightmost = 5 时最大值 44 正好在末尾，交换等于原地不动。继续到 rightmost = 1，最终得到 {3, 8, 10, 22, 22, 44, 46, 51}。

考点

选择排序每一轮只交换一次（也可能不交换），交换发生在“未排序部分的最大值”与“未排序部分的最后一个位置”之间，而不是与整个数组的末尾。

L9 p.15–16

8.8 冒泡排序：交换相邻的逆序对

冒泡排序是最简单的排序算法之一：它反复检查相邻的两个元素，如果顺序不对就交换。这样较大的元素会一路被“推”向右边，讲义的原话是最大的元素“冒泡”到数组末尾；然后对剩下的未排序部分重复同样的过程。

算法同样是四步：把整个数组定义为未排序部分；只要未排序部分非空，就对其中每个元素检查“是否比右邻居大”，是则交换；然后把未处理部分缩小一个；最后输出结果。实现上外层变量 i 表示未排序部分的右端，内层 j 从 0 走到 i − 1，正好覆盖所有相邻对。

int temp;

for (int i = arraySize - 1; i > 0; i--) {      // loop over the unsorted array
    for (int j = 0; j < i; j++) {              // move the largest element to the right
        if (A[j] > A[j + 1]) {                 // swap if greater
            temp = A[j];
            A[j] = A[j + 1];
            A[j + 1] = temp;
        }
    }
}

用同一个数组走第一轮：10 与 22 顺序正确，不动；22 与 3 逆序，交换，数组变成 {10, 3, 22, 22, 46, 51, 8, 44}；22 与 22 相等，不交换；22 与 46、46 与 51 都正确；51 与 8 交换；51 与 44 交换。第一轮结束时 51 落在最后一个位置，后面的轮次不再碰它。

内层上界写成 j < i 而不是 j < arraySize − 1，是因为右侧 i 之后的元素都已经就位；如果照抄成 j <= i，第一轮 j 可以取到 i = arraySize − 1，语句 A[j + 1] 就会读到数组之外。

易错

选择排序的内层是“找最大值”，循环里只更新下标、不交换；冒泡排序的内层是“比较相邻对”，每次逆序都立刻交换。把两者的循环体抄混，程序仍然能跑，但已经不是讲义里的算法。

辨析

两种排序都把“已排好的尾部”逐步扩大：选择排序靠一次远距离交换把最大值送到尾部，冒泡排序靠一路相邻交换把它推过去。前者交换次数少，后者在每一轮里可能交换很多次。
