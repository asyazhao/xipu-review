字符串与静态方法

Strings & Static Methods

来源 W4 · 术语 10 个

虚线下划线为术语；悬停查看中文、英文与释义，完整词典见“术语”。

本讲把“文本”拆成 char、char[] 与 String 三种表示，讲清编码、比较、查找、截取、替换与不可变性，再把重复代码收进方法：static 与实例、返回值、参数、命名与重载。

本章要点

  • char 是 16 位无符号整数，单引号；双引号是 String，长度可以为 1 但类型不同。
  • char 存 UTF-16 码元，0 到 65535；超出 U+FFFF 的字符需要一对代理项，length() 计为 2。
  • char 参与算术会提升为 int：'A' + 'C' 得 132，'C' − 'A' 得 2。
  • String 变量存引用；字面量共享池中对象，new String(...) 另建对象，== 比较引用、equals 比较文本。
  • compareTo 返回负数、零或正数，表示在前、相同、在后。
  • substring(start, end) 不含 end；indexOf 找不到返回 −1；越界抛异常。
  • String 不可变，所有“修改”都返回新对象；频繁修改用 StringBuilder。
  • 方法是类中具名的可复用代码块；static 方法用类名调用，实例方法必须先有对象。
  • 方法签名 = 方法名 + 参数类型列表；仅返回类型或参数名不同不构成重载。

4.1 文本的三种表示：char、char[]、String

程序里的文本有几种存法。单个字符用 char，它是基本类型，用单引号写：char drinkSet = 'A';。若要一个对象而不是基本值，用包装类 Character：Character drinkSet = 'A';。一串字符可以用字符数组 char[] reply = {'T','a','k','e','a','w','a','y'};。整段文本则用 String：String reply = "Takeaway";。

引号决定类型，这一点必须清楚：'M' 是 char；"M" 是长度为 1 的 String；"Mixue" 是长度为 5 的 String；'Mixue' 不合法，因为 char 字面量放不下多个字符。'7' 与 7 都合法但值不同：'7' == 7 为 false，字符 '7' 的码元值是 55。

char 与 char[] 的差别在“一个值”与“一排值”。char[] drink = {'t','e','a'}; 有 3 个槽位，索引 0、1、2，drink[0] = 'T' 只替换第一个字符，数组长度仍是 3，用 drink.length 取长度（没有括号）。String 用 length()（有括号）——这是数组与 String 最容易混的一处。

考点

char 用单引号、String 用双引号；'7' 的值是 55 而不是 7；数组取长度用 .length，String 用 .length()。

4.2 编码、char 运算与转义

字符在机器里是数字。ASCII 覆盖 0 到 127，讲义给了完整对照表：48 是 '0'、65 是 'A'、97 是 'a'、32 是空格（SP）、10 是换行（LF）。Unicode 是更大的字符集，一个 char 是 16 位无符号整数，范围 0 到 65535，即 216 = 65536 个值；换写成十六进制是 0x0000 到 0xFFFF，Unicode 记法是 U+0000 到 U+FFFF，Java 的转义写法是 \u0000 到 \uFFFF。每组 4 位二进制对应 1 位十六进制，一个 Java char 存一个 UTF-16 码元。

有些字符超出 U+FFFF，例如冰淇淋 🍦 是 U+1F366，一个 char 放不下，UTF-16 用两个 16 位码元表示：高代理项 \uD83C 加低代理项 \uDF66，合起来叫代理对surrogate pair。高代理范围 U+D800 到 U+DBFF，低代理范围 U+DC00 到 U+DFFF，单独的代理项不构成完整字符。因此 "\uD83C\uDF66".length() 是 2，而 codePointCount(0, length()) 是 1——length() 数的是码元，不是可见字符。

char 参与算术会提升为 int：'A' + 'C' 是 65 + 67 = 132；'C' - 'A' 是 2；(char)('A' + 1) 得到 'B'。注意 "A" + "C" 得到 "AC"，那是拼接不是加法。比较也用数值码：'a' < 'b' 为 true（97 < 98），'a' == 97 为 true，大写与小写不同，'A' != 'a'。

想往字符串里放特殊字符要转义：\n 换行、\t 制表、\" 双引号、\' 单引号、\\ 反斜杠。不转义会编译失败——引号会提前关闭字面量。单引号在双引号字符串内部（如 "'s'"）不需要转义。

易错

char 是“码元”不是“可见字符”：emoji 的 length() 为 2，charAt(0) 只取到半个代理项。length() 与 codePointCount() 在含 emoji 的文本上会给出不同答案。

W4 slide 9–14

4.3 Character 包装类与字符工具

char 是基本值，Character 是它的包装对象。把 char 变成 Character 叫装箱boxing，反过来叫拆箱unboxing；Java 可以自动完成，称为 autoboxing。

char size = 'm';
Character boxed = size;        // autoboxing
char again = boxed;            // unboxing

Character manual = Character.valueOf(size);
char restored = manual.charValue();

拆箱 null 会抛 NullPointerException——因为 null 没有可提取的值。Character 的静态工具方法分两类：判断类返回 boolean，包括 isLetter、isDigit、isWhitespace、isLetterOrDigit、isUpperCase、isLowerCase；转换类返回 char，包括 toUpperCase 与 toLowerCase。

还有一个容易记错的：Character.digit('7', 10) 返回整数 7，而不是码 55；如果该字符在指定进制下不是数字，返回 −1。

辨析

Character.isDigit('7') 回答“是不是数字字符”（boolean）；Character.digit('7', 10) 回答“它的数值是多少”（int，7）。两者常被混为一谈。

W4 slide 15–16

4.4 String 的创建、引用与字符串池

String 变量里存的是引用reference，指向堆上的对象。创建方式有几种：字面量 String a = "Snow King";、new String("Snow King")、new String(charArray)，也可以用 toCharArray() 反向得到 char[]。String.valueOf(true) 得到 "true"，String.valueOf(2) 得到 "2"。

String usingLiteral = "Snow King";
String usingLiteralAgain = "Snow King";
String usingNew = new String("Snow King");

System.out.println(usingLiteral == usingLiteralAgain); // true
System.out.println(usingLiteral == usingNew);         // false

原因在字符串池string pool：相同的字面量共享同一个对象，new String(...) 则另建一个独立对象。所以 == 比较的是引用（地址），equals() 比较的才是文本内容。

还要分清空串与 null："" 是一个长度为 0 的对象，null 表示没有指向任何对象。对 null 调用 length() 会抛 NullPointerException，而不是返回 0。另外，String declarationOnly; 只声明不赋值时处于“未初始化”状态，在赋值前读取它是编译错误，与显式赋 null 不同。

易错

""、null、未初始化是三件不同的事：空串能调用方法且 length() 为 0；null 调用方法抛 NPE；未初始化变量根本不能读，编译就过不去。

W4 slide 18–20

4.5 相等与顺序：==、equals、compareTo

String 的三种比较
写法比较什么返回
a == b引用是否指向同一对象boolean
a.equals(b)文本是否完全相同（区分大小写）boolean
a.compareTo(b)按 UTF-16 值的字典顺序负数 / 0 / 正数

equalsIgnoreCase 忽略大小写比较文本；compareToIgnoreCase 忽略大小写比较顺序。讲义用 "Lemon Tea" 与 "Snow King" 演示 compareTo：第一个不同字符是 'L' 与 'S'，差值 76 − 83 = −7，所以前者在前；反过来是 +7；完全相同返回 0。结果不限于 −1 与 1，只要看符号即可——小于 0 在前、等于 0 相同、大于 0 在后。

compareTo 还有两条规则：区分大小写并按 UTF-16 值比较；若一个文本是另一个的前缀，短的排在前面。

考点

判断“两个 String 内容是否相同”必须用 equals，不能用 ==；== 为 true 时 equals 一定为 true，反之不成立。

W4 slide 20–21

4.6 拼接、格式化、索引与截取

+ 可以连接文本，规则是“从左到右，一旦有 String 参与，该次运算就变成拼接”。所以 "Total: " + 6 + 2 得到 "Total: 62"，而 "Total: " + (6 + 2) 得到 "Total: 8"。字符也遵循同一规则："" + 'H' + 'i' 得到 "Hi"，但 'H' + 'i' + "" 先把两个 char 加成 177，再加空串得到 "177"——在末尾补空串救不回已经发生的数值加法。

另外两种拼接方式是 concat 与 String.format：text.concat(otherText) 连接两个字符串，空格要自己加；String.format(template, values...) 返回格式化后的文本，仍需用 println 显示。占位符包括 %s 文本、%d 整数、%f 浮点、%.2f 两位小数、%c 字符、%b 布尔、%% 百分号本身、%n 平台换行符；参数从左到右填空，%% 与 %n 不消耗参数。

取字符与取子串都要守住边界。合法索引是 0 ≤ index < length()：name.charAt(0) 取首字符，charAt(length() - 1) 取末字符；charAt(-1) 或空串的 charAt(0) 都抛 StringIndexOutOfBoundsException。

substring 的规则是“含头不含尾”：order.substring(0, 5) 取索引 0 到 4，得 "Lemon"；substring(6) 从 6 到末尾，得 "Tea"；substring(5, 5) 不选任何字符，得到空串；substring(0, order.length()) 取整串。合法范围是 0 ≤ start ≤ end ≤ length()，结果长度等于 end − start，end 超过长度就抛异常。

易错

substring 的第二个参数是“结束位置（不含）”，不是“要取几个字符”。要取 5 个字符写 substring(0, 5)，不是 substring(0, 4)。

W4 slide 22–26

4.7 查找、替换、切分与去空白

indexOf 返回第一个匹配的位置，找不到返回 −1（−1 不是合法索引，只是“没找到”的标记）：order.indexOf('e') 得 1，order.indexOf('e', 2) 从索引 2 开始找，得 7，order.indexOf("Tea") 得子串起点 6，order.indexOf("Coffee") 得 −1。搜索区分大小写。

文本处理方法的差别
方法作用匹配方式
split(",")按分隔符切开，返回 String[]正则
replace("Tea","Milk")替换每一处字面文本
replaceAll("\\d","#")替换每一处正则，\d 匹配数字
replaceFirst("Tea","Milk")只替换第一处正则
trim()去掉两端 ≤ U+0020 的字符按码位范围
strip()去掉两端 Java 空白Character.isWhitespace

trim 与 strip 的差别有实际意义：\u2003 是 EM SPACE，trim() 去不掉它，strip() 可以；反过来 strip 不去 U+00A0、U+2007、U+202F、U+FEFF 等。stripLeading 只去头部、stripTrailing 只去尾部。注意所有 String 方法都不改动原对象，必须使用返回的结果。

测试类方法都返回 boolean：contains（任意位置）、startsWith（开头）、endsWith（结尾）都区分大小写；equals 精确比较、equalsIgnoreCase 忽略大小写、matches 用正则匹配整个字符串。isEmpty 判断长度是否为 0，isBlank 判断是否为空或只含 Java 空白：" " 长度为 1 所以不是 empty，但它是 blank；"" 既 empty 又 blank。

考点

replace 用字面文本、replaceAll / replaceFirst / split / matches 用正则；indexOf 找不到返回 −1；isEmpty 看长度、isBlank 看是否有非空白字符。

W4 slide 25–29

4.8 不可变性与 StringBuilder

String 的内容永不改变。方法不会改写原对象：first.toUpperCase() 返回新的文本，不赋值就丢弃；first = first.toUpperCase() 只是让 first 指向另一个对象，原来那个 "Tea" 还在。变量可以换引用，对象不能换内容——这就是不可变性immutability。

String first = "Tea";
String second = first;

first.toUpperCase();          // 结果被丢弃
System.out.println(first);    // Tea

first = first.toUpperCase();  // first 改指向新对象
System.out.println(first);    // TEA
System.out.println(second);   // Tea，second 仍指原对象

需要反复修改文本时用 StringBuilder，它是可变的：append() 在末尾追加，replace(start, end, text) 改写其中一段，最后 toString() 生成一个不可变的 String 快照。builder 的内容变了但引用不变，适合在循环里反复拼接；它的缓冲区会按需增长。

讲义还提醒：不可达的临时对象会被垃圾回收，但不一定立刻回收，所以不要依赖“反正会被回收”来写低效代码。

易错

str.toUpperCase(); 单独一行没有任何效果，必须写成 str = str.toUpperCase();。StringBuilder 则相反：sb.append("x"); 就改变了 sb 本身。

W4 slide 29–31

4.9 方法：结构、static、返回值与参数

方法method是带名字的可复用代码块，被调用时执行。把三句 “Welcome, Amy!” “Welcome, Bo!” “Welcome, Chen!” 收进一个方法，动作只写一次，变化的部分用参数表示。方法的完整解剖是：

public static String greet(String name) throws Exception { return "Welcome, " + name + "!"; }

  • public：访问修饰符，其他类也能调用。
  • static：非访问修饰符，表示通过类调用、不需要创建实例。
  • String：返回类型。
  • greet：方法名。
  • (String name)：参数列表，一个 String 参数。
  • throws Exception：可选的异常声明，说明该方法可能把异常抛给调用者。
  • { ... }：方法体；return 把结果送回调用者。

方法定义在类里面、main 外面。访问范围由修饰符决定：private 只有声明它的类内部可用；不加修饰符是同包可用；protected 是同包加包外子类（有额外限制）；public 是只要能访问到该类就能用。讲义用四个文件演示：同一个类里调用 private 方法可以编译，同包的其他类不行，包外子类不行，包外非子类也不行——import 只让你能写类名，不会给方法授权。

static 与实例的区别在于“要不要对象”：static 方法属于类，写 SnowKing.brand()，不需要实例，也没有 this；实例方法属于对象，必须先 SnowKing king = new SnowKing(); 再 king.greet()，用类名直接调用实例方法会编译错误。两者都可以是 public，访问权限与 static 是两个独立决定。

返回类型分两类：void 不返回值，只能当语句调用，可以用 return; 提前退出；其他类型必须返回值，调用者可以存起来或直接使用。非 void 方法的所有正常结束路径都必须返回与声明类型兼容的值，void 则不能返回值。注意“返回值”与“打印”是两件事：return 只把值交回调用者，打印是调用者做的。

参数属于定义，每个参数都有类型和名字；实参argument由调用者提供，个数、顺序、类型都要与参数匹配。方法可以有 0 个、1 个或多个参数，零参数时圆括号仍要写。

考点

static 不是访问修饰符；static 方法没有 this，不能直接调用本类的实例方法；非 void 方法每条正常路径都要 return；返回类型写在方法名之前。

W4 slide 34–39

4.10 命名、重载与签名

方法名是标识符identifier：日常命名以字母、下划线 _ 或美元符 $ 开头，后续字符可以是数字，允许 Unicode 字母。因此 serveTea、serve2Cups、_prepare、$price、点单 都合法；2serve（数字开头）、serve-tea（连字符）、serve tea（空格）、class 与 return（保留字）都不合法。名字区分大小写，serveTea 与 ServeTea 是两个名字；true、false、null 是字面量不是关键字，但也不能当名字；Java 9 起单个下划线 _ 也被禁止。约定是用动词、小驼峰（lowerCamelCase），如 takeOrder、calculateTotal、isReady——这是风格约定，不是编译器规则。顺带一提：main 不是保留字。

重载overloading是同一个类里用同一个名字、不同的参数列表定义多个方法。方法签名method signature = 方法名 + 有序的参数类型，例如 order(String, int)。返回类型、参数名、修饰符、throws 都不属于签名。

static String order(String drink)              { return drink; }
static String order(int cups)                  { return cups + " teas"; }
static String order(String drink, int cups)    { return cups + " x " + drink; }
static String order(int cups, String drink)    { return cups + " x " + drink; }

这四个方法签名互不相同，所以可以共存：order("Tea") 得 "Tea"，order(2) 得 "2 teas"，order("Tea", 2) 与 order(2, "Tea") 都得 "2 x Tea"。反过来，同一签名出现两次就是编译错误：只改返回类型（static int order(String drink)）与第一个冲突；把参数名从 drink 改成 name，签名仍是 order(String)，同样冲突。编译器在编译期选出最具体的适用重载，没有匹配或有歧义都报错。

本讲最后把方法组合成一个点单程序：isValidSize 校验输入（strip 后长度必须为 1，转大写后是 S/M/L 之一）、makeReply 组装回复、sizeName 把字符映射成 Small/Medium/Large、main 负责读一行并打印。之后的点单版本再加 readCodes（String → char[]）、drinkName（char → String）与 buildReceipt（char[] → String，用 StringBuilder 逐行 append）。这种“一个小方法只做一件事”的拆法，正是本讲想传达的设计习惯。

易错

只改返回类型不叫重载，把参数名改掉也不叫重载——两者都会与已有方法签名冲突。真正能重载的是参数个数、参数类型或类型顺序的改变。
