函数：抽象、传值与传引用

Functions: Abstraction, Pass by Value & Reference

来源 L10–11 · 术语 8 个

本章回答两个问题：怎样把一个复杂程序拆成可复用的部件（分解与抽象），以及函数被调用时数据到底发生了什么（传值与传引用）。理解内存里两块独立的数据区，是后续学数组、指针与递归的基础。

本章要点

  • 分解把程序拆成自包含、可复用的部件；抽象隐藏细节，只保留“做什么”。
  • 函数是黑箱：接口（签名/原型）说明输入输出，定义藏起实现，二者可以分开写。
  • 函数必须先声明后使用；定义写在 main 之前时可以省掉原型。
  • 传值把实参的值复制给形参，两块数据区互不影响，修改形参不会改动调用者。
  • 传引用把地址交给函数，形参与实参是同一块存储，因此可以带回多个结果。
  • 整个数组传参时自动按引用传递，只需首元素地址与维度；多维数组除第一维外都必须写明。
  • 同名函数靠参数的类型与个数（签名）区分，这叫函数重载。

9.1 分解与抽象：把代码变成黑箱

讲义先盘点已经学过的语言机制：基础类型（primitives）、复杂表达式、分支（if-else、if-else if、switch）与循环（for、while、do-while）。按讲义的说法，原理上这些已经足够完成任何可计算的任务，但还缺两个最重要的概念——分解decomposition与抽象abstraction。

分解要解决的问题是：怎样把程序切成若干个自包含（self-contained）的部分，并且能组合起来解决当前问题。讲义对“自包含”给了一个可操作的定义——这些部分只使用传给它的输入和“基本”操作来完成计算；理想情况下，这些部分还能被别的程序复用。它用圆面积做例子：先写 pi = 3.14、r = 2.5，再算 area = pi * r²。把“算圆面积”独立出来，就是一次最小的分解。

抽象要解决的问题是：怎样忽略不必要的细节。讲义把它概括为一句话——把“它做什么”（what）与“它实际怎么做”（how）分开。创建部件并把细节抽走，才能写出复杂的代码而不被复杂度淹没；否则每读一行都要同时想着十件无关的事。

两者合起来就是讲义反复强调的大图景：用黑箱black box的方式做抽象，用拆成自包含部分的方式做分解。写代码的人负责细节并设计接口，用代码的人只需要接口，不需要也不想看细节；黑箱还可以在程序的不同位置重复使用，从而不必复制粘贴。

9.2 函数：黑箱的代码形态

函数function在别的语言里也叫方法（method）或过程（procedure）。讲义提醒，其实早就用过函数了——初始化随机数发生器的 srand(time(0)) 就是一次函数调用。函数让我们把一段代码装进黑箱：它捕获达成某个计算目标所需的操作序列，用指定的输入产生输出，同时把“怎么算”的细节藏起来。

每个函数都有一份规格说明specification，在 C/C++ 里用注释表达（可选但推荐）。规格的含义是：只要使用者提供的输入满足所述条件，函数就按规格产生输出，包括注明的副作用。讲义给的例子用文档注释写清了参数 ch 的含义与返回 true/false 的条件。

函数靠签名signature被识别，签名又叫函数原型（function prototype），它声明接口——输入与输出参数——而把实现留给定义。一般形式是“返回类型 + 函数名 + 参数表”，参数可以有 0 个或多个：

bool isAlphaNumeric(char ch);   // returns bool, takes one char
void printCard(int);            // void function: returns no value

第二行说明了两点：参数表里可以只写类型不写名字；返回类型为 void 表示这个函数不返回值，只做事（比如打印一张牌）。讲义另外给出一条放置规则：函数的定义可以放在程序中任何位置，只要在原型之后；如果定义直接写在 main() 之前，就不必再提供原型，因为函数在使用之前已经被定义。反过来，函数必须先声明后使用，定义的细节可以晚一点再给。

C++ 程序通常的组织形式因此是固定的四段：include 语句、函数原型、main() 函数、用户自定义函数。

考点

原型与定义的区别：原型只有返回类型、函数名与参数类型，以分号结束；定义带函数体。编译器只需要看到原型就能检查调用的写法是否正确。

L10 p.9–13

9.3 自顶向下：函数如何组织一个程序

有了黑箱抽象，就可以把一个复杂问题拆成若干更小的子问题，子问题再拆成子子问题，每个都能单独求解——讲义把这种思路叫自顶向下编程top-down programming。它画出的是一棵树：根是问题，往下是子问题，再往下是子子问题。

每个问题或子问题都用一个函数（或一个类，讲义说后面再讲）来解决。讲义把函数的用处归成四条：把代码分成逻辑块；把概念（做什么）与实现（怎么做）分开；让程序更容易理解和修改；同一个函数可以在同一程序里被调用多次，从而复用代码。最后一句是关键：分解依赖抽象，才能用简单函数搭出复杂应用。

C/C++ 允许同时使用内部（用户自定义）函数与外部函数。外部函数通常按主题收进专门的库，例如 iostream、cstdlib、cmath；讲义提到常用库函数的清单放在 Learning Mall 上。库函数就是别人写好的黑箱——可以直接调用，但也意味着它的行为要靠文档和测试来确认。

辨析

分解与抽象不是同一件事：分解回答“切成几块”，抽象回答“每块对外露出什么”。只有分解没有抽象，切出来的仍然是彼此纠缠的代码；只有抽象没有分解，黑箱里会塞进整座程序。

9.4 调用：实参与形参的一一对应

函数调用（invoke）的语法是“函数名 + 括号里的参数表 + 分号”。讲义强调一条硬性要求：调用中的实参actual argument与定义中的形参formal parameter必须一一对应——个数、类型、顺序都要对得上。

以打印扑克牌为例：先声明 void printCard(int num);，然后在 main() 里对五张牌各调用一次。每次调用把一张牌的点数交给同一个函数，函数内部按 1、2–10、11、12、13 分别输出 A、数字、J、Q、K，其它值则向 cerr 报错。五次调用共用一份代码，这正是“复用”最直观的样子。

void printCard(int num);

int main() {
    int c1, c2, c3, c4, c5;
    // pick cards ...
    printCard(c1);
    printCard(c2);
    printCard(c3);
    printCard(c4);
    printCard(c5);
    return 0;
}

实参不一定是变量，也可以是表达式。讲义的绝对值例子写的是 diff = absolute(x - y);：先算出 x − y 的值，把这个值作为实参传进去，函数返回的结果再赋给 diff。函数定义里用三元运算符写成一行——num < 0 ? -num : num，等价于一个 if-else。

易错

调用写的是实参的“值”，不是形参的名字。printCard(c1) 与定义 void printCard(int num) 中的 num 没有任何名称上的联系，名字可以完全不同，能对上的是位置与类型。

9.5 传值：内存里发生了什么

讲义用一张内存图解释调用过程。调用者 main() 的数据区里有 x = 4、y = 5、diff；被调用者 absoluteNum() 的数据区里有形参 num 与局部变量 result；此外还有一块临时变量（讲义记作 temp.xxxx）用来保存 x − y 的值 −1。整个过程分三步：把值传进去、在函数里计算、把结果返回。

关键在于两个数据区彼此独立。函数里对 num 或 result 的任何修改，都只发生在被调用者的数据区；调用者的 x、y 一个字节都没变。讲义用一句话点明：它们使用的是不同的内存位置（different memory locations）。这种参数传递方式就叫传值pass by value。

讲义用一个小程序检验这件事：sum(int a, int b) 里执行 a = a + b 再返回 a，主程序令 x = 3、y = 5、z = sum(x, y)。程序结束时 x、y、z 分别是 3、5、8。a 被改成了 8，但 x 仍是 3——形参是副本。

考点

传值的三条结论：实参的值被复制给形参；形参的改变不影响实参；函数内声明的局部变量在函数结束时全部丢失，唯一能带出函数的信息是 return 语句的返回值。

L10 p.18–21

9.6 传值的用法与边界

传值并不是缺陷，而是默认行为。讲义给了两个正常使用的例子。第一个是 print_sum_average(double a, double b)：把两个数传进去，函数内部算 sum 与 average 并直接打印；因为结果通过屏幕输出，不需要带回调用者，void 加传值就够了。

void print_sum_average(double a, double b) {
    double sum, average;
    sum = a + b;
    average = sum / 2;
    cout << "Sum: " << sum << endl;
    cout << "Average: " << average << endl;
}

第二个是英寸换算：int feet(int inches) 返回 inches / 12，int rinches(int inches) 返回 inches % 12。两个函数各算一件事，主程序一次调用就拼出“几英尺几英寸”。这里能看出分解的好处——整数除法与取余被分别封进两个黑箱，主程序不必关心换算细节。

但传值有一条硬边界：它只能带回一个值（return 的那一个）。如果想让函数同时给出和与平均值、同时交换两个变量、同时返回最大值和它的下标，仅靠传值做不到。讲义正是用这个问题引出下一章的传引用：一个函数怎样才能返回多于一个数据对象？

易错

在传值函数里改形参，回到 main 后再打印实参，看到的仍是原值。把“函数里明明改了”当成程序错误去查，往往查错了地方——要检查的是这个参数到底按值还是按引用传递。

L10 p.19–24

9.7 传引用：把地址交给函数

要让函数带回多个结果，就要用传引用pass by reference。讲义的定义很直接：传给函数的是参数的引用（也就是地址），而不是它的值；如果函数改变了参数的值，这个改变会反映到调用它的程序里（调用者叫 caller，被调用者叫 callee）。语法只在类型后面加一个 &：

void increment(int &n) {   // pass by reference
    n++;
    cout << "n at function: " << n << endl;
}

与传值版本对照最清楚：主程序里 num = 10，调用 increment(num)。若形参写成 int n，输出是“n at function: 11”和“num at main: 10”；若写成 int &n，输出是“11”和“num at main: 11”。同一份函数体，只差一个 &，主程序里的 num 就从 10 变成了 11。

更实用的例子是一次算两个结果。讲义声明 void sumAndAverage(double n1, double n2, double &sum, double &average);：前两个参数按值传（只需要读），后两个按引用传（需要写回）。函数体只有两行：sum = n1 + n2; average = sum / 2;。主程序调用后直接打印 sum 与 average，输入 1.1 与 2.2 时得到 3.3 与 1.65。

讲义还给了排序三个数的例子：写一个 void swap(int &x, int &y) 交换两个整数，主程序只需三次比较与最多三次 swap，就能把 first、second、third 排好。交换这件事必须按引用做——按值交换只会交换两个副本，调用者的变量纹丝不动。

考点

同一个函数可以混用两种传递方式：只读的输入按值传，需要写回的结果按引用传。看到参数表里有 &，就要意识到这个实参可能被函数改写。

L11 p.2–8

9.8 数组传参：元素、整体与多维

数组元素是个普通变量，可以按值传，也可以按引用传。讲义对比了两段代码：printCard(cards[n]) 把一张牌的值复制进函数，函数改不到数组；swap(a[3], a[6]) 把两个元素按引用传进去，函数内部的交换直接作用在数组上，输出从 {1, 4, 6, 72, 46, 73, 21, 35} 变成 {1, 4, 6, 21, 46, 73, 72, 35}。

整个数组传参则是另一套规则：只需要数组首元素的地址与数组的维度，其余部分会自动按引用传递。讲义的原话是“the remainder of the array will be passed by reference automatically”，所以形参写成 int cards[] 时不必再加 &。

void shuffleCards(int cards[], const int numOfCards, const int numOfSwap) {
    for (int i = 0; i < numOfSwap; i++) {
        int first = rand() % numOfCards;
        int second = rand() % numOfCards;
        int temp = cards[first];
        cards[first] = cards[second];
        cards[second] = temp;
    }
}

这段洗牌代码里有两种参数修饰：cards[] 没有 const，因为它要被改写；numOfCards 与 numOfSwap 前面加了 const，表示它们是常量、函数内不能改。这是一个很实用的习惯——把“只读”写进签名，让编译器帮忙拦住误改。

输出型数组同样按引用传。讲义的 addArray 声明为 void addArray(const int size, const double a[], const double b[], double c[])：a、b 标了 const 只读，c 没有 const，函数把 a[i] + b[i] 写进 c[i]，调用者的 c 数组被填满。

多维数组的规则更严：只有第一维的大小可以省略，第二维起必须写明。原型写作 void displayBoard(int b[][4]);，定义可以写成 int b[][4] 或 int b[4][4]，但绝不能写 b[][]。

易错

“数组自动按引用传递”不等于“数组元素也自动按引用传递”。传整个数组时不用 &，是因为传的本来就是首地址；但单独传一个元素 a[3] 时，它仍按普通变量规则处理，要写 & 才能改到原元素。

L11 p.9–16

9.9 重载与“不要相信任何函数”

讲义在结尾给了几条关于函数的提醒。第一条：函数只有在被调用时才有用，写而不调等于没写。第二条：同一个类里可以有两个以上同名函数，只要它们的签名不同——参数的类型与个数不同即可区分，这叫函数重载function overloading。讲义给的例子是 bool isEven(int num) 与 bool isEven(string str)：一个判断整数奇偶，一个先把字符串转成整数（atoi(str.c_str())）再判断。

第三条也是最重要的一条：要验证结果，尤其是使用别人写的函数时。讲义的原话是“不要假设你用的任何函数是正确的”，连语言自带的函数也一样；它甚至给了一个“二分查找里的 bug”的视频链接作为反面教材。这正好呼应第 8 章：二分查找的边界写错一位，代码能编译、能跑，却会在某些输入上给出错误答案。

讲义把这一节的忠告压缩成三句：不要一上来就写代码；验证你用到的每一个函数；经常测试，用打印来调试。配合第 12a 讲的 driver 与 stub，这几句话就变成了可执行的流程——先写一个只会打印参数的空壳，确认调用链通了，再往里填真正的计算。

辨析

重载看的是签名（参数的类型与个数），不是返回类型。两个函数只有返回类型不同、参数完全相同，不构成重载，编译器无法在调用处区分它们。
