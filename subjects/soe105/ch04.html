算法设计与 C/C++ 基础

Algorithm Design & C/C++ Basics

本讲先用“最少钞票张数”的例子说明算法必须先想清楚再实现，再系统给出 C/C++ 的语法基础：注释、标识符、头文件、数据类型、常量与变量、赋值、算术运算、类型转换、优先级与标准输入输出。

本章要点

  • 算法要先证明再实现；找零例子说明“看起来对”的算法在 HK$80 上会失效。
  • 好的算法可用可检验的性质来验证，例如至多一张 10 元、20 元与 10 元合计小于 50 元。
  • 标识符由字母或下划线开头，区分大小写，不能是保留字，不能含特殊字符。
  • #include <iostream> 用于预定义头文件，#include "my_lib.h" 用于用户自定义头文件。
  • 基本类型的大小以字节计，且可能随硬件架构变化；变量类型与值必须一致。
  • 常量在声明时赋值，之后不可改；变量必须先声明、后使用。
  • 整数相除会截断小数；要得到实数结果必须做类型转换。
  • 优先级：括号 → 一元 → * / % → + - → 关系 → 逻辑 → 赋值。

4.1 找零问题：先想清楚，再写代码

讲义接着上一讲的兑换问题往下走：算出金额后，还要把现金交给买家，公司需要决定“最少需要多少张钞票”。给定的背景知识是四条替换规则：两张 10 元可换一张 20 元；两张 20 元加一张 10 元可换一张 50 元；三张 20 元可换一张 50 元加一张 10 元；两张 50 元可换一张 100 元。

按顺序执行四条替换规则的初版算法是：先数出 10 元张数，再依次把两张 10 元换成 20 元、把两张 20 元加一张 10 元换成 50 元、把两张 50 元换成 100 元。看起来合理，但讲义直接用 HK$80 测试就发现了错误——初版算法漏掉了“三张 20 元换 50 + 10”这条规则，结果不是最少张数。补上该规则后，HK$80 才得到正确答案。

讲义由此给出一个更简洁的算法：依次求 100 元、50 元、20 元、10 元的“最大张数”，每一步都用整除求张数、用取模求余额：

100_dollars   = total_chinese_yuans / 100;
remain_dollars = total_chinese_yuans % 100;

50_dollars    = remain_dollars / 50;
remain_dollars = remain_dollars % 50;

20_dollars    = remain_dollars / 20;
remain_dollars = remain_dollars % 20;

10_dollars    = remain_dollars / 10;

这版算法不需要“反复替换”，因为面额之间满足特定的整除关系，从大到小贪心取最大张数即可。讲义用一张大写的“BIG IDEA”总结这一段：先把算法想清楚并证明，不要急着实现（THINK and PROVE your ALGORITHM FIRST! DON'T RUSH TO IMPLEMENTATION!）。

易错

“按规则反复替换”不等于“最优”。初版算法在 HK$80 上失败，说明凭直觉排列规则可能漏掉组合；能用整除/取模直接算的场合，优先用直接算法。

4.2 如何验证一个算法

算法写完后怎么测？讲义给出的不是“多试几个数”，而是一组必须始终成立的性质：

  • 至多只有一张 10 元钞票；
  • 所有 20 元与 10 元钞票的合计金额小于 50 元；
  • 所有 50 元、20 元与 10 元钞票的合计金额小于 100 元。

这三条其实是在验证“没有可替换的组合被漏掉”：如果出现两张 10 元，就能换成一张 20 元；如果 20 元与 10 元的合计达到 50 元，就能换成 50 元；依此类推。性质成立，则结果在给定面额体系下就是最少张数。

这种“用不变式检验算法”的做法，比枚举测试用例更有说服力：测试只能说明某些输入正确，性质说明所有合法输入都正确。

考点

算法验证的两条路径：用测试数据覆盖边界，用不变式/性质证明对所有输入成立。讲义对找零算法给出的是后者的三条性质。

L03 p.8–9

4.3 注释与标识符

注释是解释性文字，不属于程序本身。C/C++ 有两种写法：// 开始单行注释；/* 与 */ 包裹多行注释。

// A double slash starts a single line comment

/*
   A slash followed by an asterisk marks the
   start of a multiple line comment.
   It ends with an asterisk followed by a slash
*/

标识符identifier是变量、常量、函数等的名字。规则是：以字母或下划线（_）开头，后面接字母、数字或下划线；不能是 C/C++ 的保留字reserved word（如 int、return、while、class），因为保留字在语言中有特殊含义；不能包含特殊字符。

名字区分大小写：Hello、hello、whoami、whoAMI、whoAmI 是五个不同的标识符。反过来，X=y、J-20、#007、third-side 都不是合法标识符——等号、减号、井号都不是标识符允许的字符。

讲义附了一条实践建议：选择有意义、易记的名字。名字是给人读的，编译器并不在意你叫 n 还是 numberOfStudents，但三个月后的你会在意。

易错

下划线可以开头，数字不可以；“区分大小写”意味着 Total 与 total 是两个变量，拼错大小写不会报错，只会得到一个未声明的名字或另一个变量。

L03 p.15–16

4.4 头文件与标准库

编译器指令 #include 指向一个头文件header file，其中含有库函数或变量的声明。编译器在编译程序之前先读入该文件的内容，被包含的文件与程序一起编译。两种形式：

  • #include <iostream>：用于预定义文件（标准库）；
  • #include "my_lib.h"：用于用户自定义文件。

讲义列出几个常用库：#include <iostream> 是新的输入/输出库；#include <iostream.h> 是旧 I/O 库；#include <stdio.h> 提供标准函数；#include <math.h> 提供数学函数；#include <stdlib.h> 含随机函数；#include <time.h> 提供时间函数。

关键的一句是：using namespace std; 表示使用新的 C++ 库；如果省略这一行，程序会加载旧的 iostream 库，可能引起错误。这解释了为什么每个示例程序都同时出现 #include <iostream> 与 using namespace std;。

辨析

尖括号 < > 与双引号 " " 的区别在搜索位置：前者用于系统/标准库的预定义文件，后者用于用户自己写的头文件。

4.5 数据类型与内存占用

数据类型data type是一种基本的数据抽象，它刻画被处理数据的本质。讲义列出标准/基本类型及其典型字节数：

基本数据类型与典型内存占用
类型含义字节数
short短整型2
int整型4
long长整型4
float实数（单精度）4
double双精度实数8
char单个字符1
void未指定类型（无值）—

讲义特意加了两条限定：不同数据类型占用的内存字节数可能随硬件架构变化；许多类型还分 signed 与 unsigned 版本。因此上表是“典型值”，不是语言保证的常量。void 是特殊类型，表示“没有类型”（nothing or anything）。

还有一条硬规则：变量类型与值必须一致。把一个实数塞进 int，或把一个字符塞进 double，编译器可能只给警告甚至默默转换，但结果往往不是本意。

考点

记住典型字节数：short 2、int 4、long 4、float 4、double 8、char 1。同时记住“大小可能随架构变化”，考试若问“是否固定”，答案是否定的。

L03 p.19

4.6 常量与变量声明

常量constant表示永久的值，声明语法为 const <type> <identifier> = <constant expression>;。它的值只能在声明时设定，之后不能修改。讲义给出两个例子：const double pi = 3.14159; 与 const int DOLLAR2CENTS = 100;。常量的价值在于可读性与可维护性——把 100 写成一个有名字的常量，改一处即可全局生效。

变量variable最好理解为一个装值的容器/盒子（container/box）：它只能有一种类型。声明语法为 <type> <identifier>; 或 <type> <identifier> = <expression>;。例如 int nickel; 与 int penny = 10;。

变量必须先声明后使用。讲义给了一个反例：在 main() 里直接写 x = 5; 是非法的，因为 x 没有被声明——编译器不知道 x 的类型，也就不知道该分配多少内存、按什么规则解释这段字节。

int main() {
    x = 5;   // illegal: x was not declared
}

易错

const 常量与字面量不是一回事：const int DOLLAR2CENTS = 100; 之后不能再写 DOLLAR2CENTS = 200;，否则是编译错误。

L03 p.20–21

4.7 内存刻画与赋值

讲义用一张内存示意图把“变量是盒子”落到实处：内存按地址编号（1001、1002……），每个变量占据若干连续字节，格子里的内容就是当前值。图中 float y = 12.5; 占 4 字节，int temperature = 32; 占 4 字节，char letter = 'c'; 占 1 字节，而 int number; 只有地址、没有值——因为它尚未初始化。

赋值语句的语法是 <identifier> = <expression>;。讲义强调三点：C/C++ 中变量不会自动初始化；变量必须先被赋值才能使用；一旦值被放入变量，它会一直留在那里，直到程序改变它。

int n, m, k;        // declaration only, not initialized
n = 5;
m = 6 + (4 * 3);
k = (n * 2) + m;
k = k / 2;

赋值是“用右边的值覆盖左边的格子”，所以 k = k / 2; 合法：先算右边，再写回左边。这也解释了交换两个变量为什么需要第三个变量：

int value1 = 10;
int value2 = 20;
int temp;

temp = value1;    // temp = 10
value1 = value2;  // value1 = 20
value2 = temp;    // value2 = 10

若直接写 value1 = value2; value2 = value1;，第一步就把 value1 的旧值覆盖了，第二步只是把同一个值再抄一遍，交换失败。

考点

交换两值必须借助临时变量；赋值是覆盖而非“相等”，a = b 表示把 b 的值放入 a，不是数学上的等式。

L03 p.22；L04a p.5–6

4.8 算术运算符与整数除法

C/C++ 的五个算术运算符是 +、-、*、/、%（取模）。前四个遵循通常的优先级，例如 5 + 2 * 3 = 11；括号可改变运算顺序。C/C++ 与数学的差别在于它严格区分整数与实数：100 是 int，而 100.0、100.000、100. 都是 double。

运算结果类型由操作数类型决定：int 与 int 得 int；int 与 real、real 与 int、real 与 real 都得 real。因此整数除法会截断小数部分：3/2 得 1，4/6 得 0，10/3 得 3。这不是四舍五入，而是直接丢弃小数位。

算术运算的结果类型
操作数类型结果类型示例
int, intint10 / 3 得 3
int, realreal10 / 3.0 得 3.333…
real, intreal3.0 / 2 得 1.5
real, realreal3.0 / 2.0 得 1.5

取模 % 只用于整数，得到余数。它在前面的找零算法里反复出现：remain_dollars % 50 就是“付完 100 元后剩下的不足 50 元的部分”。

易错

3/2 是 1 而不是 1.5；只要两个操作数都是整数，结果就是整数。写成 3/2.0 或先把一个操作数转成 double，才会得到 1.5。

L04a p.8

4.9 类型转换、优先级与标准输入输出

类型转换type conversion（又称 casting）用于改变表达式的类型，语法为 variable1 = (type) variable2; 或 variable1 = (type)(expression);。讲义用一组对比说明“转谁”很关键：

int x = 1, y = 2;
double result1 = x / y;                  // 0.0  (int/int 先截断)
double result2 = double(x) / y;          // 0.5
double result3 = x / ((double)(y));      // 0.5
double result4 = (double)(x) / (double)y;// 0.5
double result5 = (double)(x / y);        // 0.0  (先算完再转)

规律是：转换发生在运算之前才有意义。result5 先把 1/2 算成 0，再转成 0.0，转换来得太晚。

运算符优先级从高到低为：括号 ( ) → 一元运算符 ! → * / % → + - → 关系 < <= >= > → 相等 == != → 逻辑与 && → 逻辑或 || → 赋值 =。同级的运算符从左到右结合。所以 mx+b 应写作 (m*x)+b，而不是 m*(x+b)。

标准输入输出来自 iostream 库。cin 是标准输入流，输入运算符 >> 从输入流（默认键盘）提取数据，会跳过空白字符，只提取符合目标类型形式的内容并自动转换类型，例如 cin >> nickels >> pennies;。cout 是标准输出流，输出运算符 << 把数据插入输出流（默认屏幕）：

cout << "The change is " << dollars << " dollars"
     << " and " << change << " 10-cents" << endl;

讲义还给了一个经典小例：读入英寸数，用 feet = inches / 12; inches = inches % 12; 把它拆成英尺与英寸。这两行正是整数除法与取模的配合用法。

考点

类型转换要作用在参与运算的操作数上，且要早于除法；cin 会跳过空白并自动按目标类型转换，因此可以连续读取多个值。
