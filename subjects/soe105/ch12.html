文件 I/O 与流

File I/O & Streams

来源 L14 · 术语 8 个

本章把“输入输出”统一成一个概念——流：键盘、屏幕、文件都是字节序列。先看标准流与文件流的打开/关闭，再用 get/put/fail/eof 读写文件，最后用 I/O 标志与操纵符控制输出的宽度、对齐、精度与格式。

本章要点

  • 文件存放在二级存储上、是永久的；读之前必须先打开，且要放在 Project 目录下。
  • 流是 C/C++ 对所有输入输出的抽象：一段（可能无限长的）按时间到达的数据元素序列。
  • cin/cout/cerr/clog 是四个标准流；>> 提取并自动跳过空白、按目标类型转换，<< 插入。
  • 文件流用 ifstream 与 ofstream，open 关联文件、close 断开，get/put 按字符读写，fail/eof 判断状态。
  • 输出格式由标志控制：skipws、left/right、fixed/scientific、showpoint；操纵符 setw、setprecision、setiosflags 修改它们。
  • setw 只作用于下一个输出项；精度对浮点数生效，对整数无效。

12.1 文件与流：两个基本概念

讲义对计算机文件computer file给了五条性质：它存放在二级存储设备上（磁盘、U 盘等）；它是永久的；它可以用来提供输入数据、接收输出数据，或者两者兼有；它必须放在 Project 目录下（不必和存放 .cpp 的源文件夹同一目录）；读取之前必须先打开。

“永久”是相对内存说的：程序结束后变量消失，文件还在。这也解释了为什么作业里的数据常用文件保存——下次运行程序时还能读到上次的结果。

流stream是 C/C++ 对所有程序输入输出的抽象，包括键盘、显示器、外部文件等等。讲义的定义是：一段（可能无限长的）数据元素序列，随时间逐步变得可用。它用一个例子说明：用户敲下 “This is characters typed using keyboard” 再按回车，程序看到的不是一句话，而是一串字符，最后跟一个换行字符；每个字符都是流里的一个元素，程序按需一个一个取。

既然流里只有字符，那些看不见的控制字符就要有写法。讲义列了一张特殊字符表示表：换行 \n（八进制 012）、水平制表 \t（011）、垂直制表 \v（013）、退格 \b（010）、换页 \f（014）、回车 \r（015）、响铃 \a（017），以及反斜杠 \\、问号 \?、单引号 \'、双引号 \"。写文件内容时如果出现这些字符，落盘的就是对应的控制码。

考点

读文件前必须先 open 建立连接，用完必须 close 断开；文件名相对 Project 目录解析，而不是相对 .cpp 所在目录。漏掉 open 就直接 >>，流没有关联任何文件，提取必然失败。

12.2 标准流：cin、cout、cerr、clog

与标准控制台交互时用 <iostream>，四个流各司其职：cin 是标准输入流，cout 是标准输出流，cerr 是标准（中间）错误流，clog 是标准（带缓冲）流。讲义的程序—流示意图把 cerr 与 clog 都画在“标准错误”这一侧：平时看到的错误信息走 cerr，需要缓冲的输出走 clog。

输入用提取运算符 >>。讲义列了它的三个特点：从输入流中提取数据；总是跳过空白；只提取“形式正确”的字符并做自动转换。所以 cin >> id >> session >> name_init >> score 可以从一行里依次取到整数、字符、字符、整数，中间的空格与换行都不需要自己处理。

输出用插入运算符 <<，把数据插进输出流或错误流：cout << "Sum = " << sum << endl; 或 cerr << "ERROR: unknown command " << command << endl;。同一个运算符，方向不同，含义相反——>> 是从流里取出，<< 是往流里放。

易错

>> 的“跳过空白”是优点也是陷阱：读字符时会跳过空格与换行，所以想读入空格必须改用 get（第 11 章）；读数字时若输入了字母，提取会失败并让流进入失败状态，后续读取全部失效。

L14 p.4–5

12.3 文件流：ifstream、ofstream、open 与 close

外部文件用 <fstream> 里的两种文件流类型：输入文件流ifstream负责读，输出文件流ofstream负责写。用法与 cin/cout 高度一致：声明流对象、把它关联到一个文件、像用 cin/cout 那样用 >> 与 <<、最后关闭。

#include <fstream>
using namespace std;

int main() {
    int data;
    ifstream ins;
    ofstream outs;

    ins.open("in_data.dat");      // associate stream with file
    outs.open("out_data.dat");

    ins >> data;                  // read from ins
    outs << data << endl;         // write to outs

    ins.close();
    outs.close();
    return 0;
}

三个动作对应三个函数：xxx.open(fname) 把流 xxx 连接到外部文件 fname，也就是打开文件；xxx.close() 断开连接，也就是关闭文件；中间的 >> 与 << 与标准流完全相同。这个设计的好处是“换一个流对象，代码不变”：把 cin 换成 ins，同一段读取逻辑就从键盘搬到了文件。

讲义强调“文件必须先打开才能读”。没有 open 就直接 >>，流没有关联任何文件，提取必然失败；而 open 的文件名默认相对于 Project 目录，不是相对于 .cpp 所在目录——把数据文件和源文件放在不同文件夹时，这一点尤其容易出错。

辨析

ifstream 只能读、ofstream 只能写，方向不能互换：读用 >> 或 get，写用 << 或 put。把流类型声明反，后面的提取或插入就无法通过编译。

12.4 文件流函数：get、put、fail、eof

除了 >> 与 <<，文件流还提供一组成员函数，讲义的清单如下：

  • xxx.open(fname)：把流连接到外部文件，即打开文件。
  • xxx.close()：断开流与文件的连接，即关闭文件。
  • xxx.get(char &ch)：从输入流 xxx 读下一个字符，放进字符变量 ch。
  • xxx.put(char ch)：把字符 ch 写进流 xxx。
  • xxx.fail()：检查是否发生了错误，即 I/O 操作是否失败。
  • xxx.eof()：检测文件结束（EOF），即下一个字符是否是文件尾。

get 与 put 是“逐字符”通道，不跳过空白、不做类型转换，读到什么就是什么；>> 与 << 是“按类型”通道，会自动跳过空白并转换格式。统计字符数、复制文件、逐行处理这类任务要用前者；读一组整数、写一张表格用后者。

fail 与 eof 是“状态查询”，返回的是条件是否成立，所以直接放在 if 或 while 的条件里。它们的区别在于：fail 回答“刚才那次操作成功了吗”，eof 回答“是不是已经到文件末尾了”。讲义的统计程序两个都用到了。

考点

get 的参数是引用（char &ch），因为它要把读到的字符写回调用者的变量；put 的参数是值，因为只往里写、不需要带回任何东西。

12.5 两个读写示例：数组反转与字符统计

第一个例子演示 >> 与 << 在文件上同样好用。程序打开 file1.dat，用 for 循环把四个整数读进数组 A；关闭输入流后打开 file2.dat，再倒着遍历数组把四个数写出去。文件里 1 2 3 4 变成 4 3 2 1，代码与“从键盘读、往屏幕写”几乎没有差别。

ifstream fin;
int A[4], r;
fin.open("file1.dat");
for (r = 0; r < 4; r++)      // read data file of four integers
    fin >> A[r];
fin.close();

ofstream fout;
fout.open("file2.dat");
for (r = 3; r >= 0; r--)     // write with numbers reversed
    fout << A[r] << ' ';
fout.close();

第二个例子统计文件的行数与字符数，用的是双层 while(true) 加 break 的结构：外层每轮处理一行，内层每轮读一个字符；读到换行或文件结束时跳出内层，行数加一，再判断是否该跳出外层。

while (true) {                    // loop for each line
    while (true) {                // loop for each character on line
        ins.get(c);
        if (ins.eof() || c == '\n') {
            break;
        }
        nChar++;
        cout << c;  outs << c;
    }
    cout << endl;
    nLine++;
    if (ins.eof()) break;
    outs << endl;
}

这段代码有两个可读的技巧。第一，条件写成 ins.eof() || c == '\n'，把“文件结束”和“行结束”合并成一个出口，避免读越界。第二，nChar 只在确认不是换行之后才自增，所以统计的是“可见字符 + 空格”，不含换行符本身。讲义给出的示例输出是 characters count: 39、lines count: 4。

易错

ins.get(c) 之后要先判断状态再用 c：文件已经结束时 c 里可能是上一次的旧值。把 nChar++ 写在判断之前，末尾会多统计一个字符。

12.6 流是对象：标志决定行为

讲义把 ios 类型的流描述成一个复杂的数据对象：它是一段无限的字节/字符序列；有专门的运算符（>>、<<）；有专门的函数（get、put 等）；还有一组修改设置（flags）用来改变 I/O 行为，以及操纵符（manipulators）与函数来修改这些标志。

由此引出两个设计问题。输入方面：提取时空白是否重要？这正是 skipws 标志管的事。输出方面：一个数据项占多少个字符宽度（field width）？靠左还是靠右（adjustment）？实数保留几位（precision）？

讲义列出的常用 I/O 标志
类别标志置位后的含义默认
输入skipws提取时跳过空白On
输出对齐left在字段内左对齐Off
输出对齐right在字段内右对齐Off
浮点格式fixed定点格式（如 59.06）Off
浮点格式scientific科学计数格式（如 5.906E1）Off
浮点格式showpoint显示小数点与尾随零Off

这张表的读法是“默认值 + 置位效果”。skipws 默认是开的——这与上一节“>> 总是跳过空白”是同一件事；要读空白就得关掉它或改用 get。left 与 right 默认都关，此时按默认方式对齐；fixed 与 scientific 默认都关，浮点数按默认格式输出；showpoint 默认关，所以 59.0 可能被打印成 59。

考点

标志是“一旦置位就持续生效”的设置，不是一次性开关。设置一次 ios::fixed 之后，后面所有浮点输出都按定点格式打印，直到被 unset 掉。

12.7 操纵符与成员函数：两种等价写法

<iomanip> 提供了四个常用操纵符，每个都有一个同名的成员函数版本：setiosflags 对应 setf（设置标志）、unsetiosflags 对应 unsetf（清除标志）、setprecision 对应 precision（设置输出数字的精度）、setw 对应 width（设置下一个输出字段的宽度）。

cout << setiosflags(ios::fixed | ios::showpoint | ios::left)
     << setprecision(2)
     << setw(8)  << id
     << setw(20) << total
     << setw(20) << average
     << endl;

// equivalent member-function form
cout.setf(ios::fixed | ios::showpoint | ios::left);
cout.precision(2);
cout.width(8);
cout << id;
cout.width(20); cout << total;
cout.width(20); cout << average << endl;

两种写法效果相同，讲义把它们并排列出，就是为了说明“操纵符只是成员函数的另一种调用方式”。操纵符写在 << 链里，读起来更像输出语句的一部分；成员函数单独成行，适合一次设置、长期生效的场合。注意 width(20) 在第二种写法里被调用了两次——因为宽度只对紧接着的那一个输出项有效。

三个设置的用途各不相同：setiosflags 一次可以按位或组合多个标志（fixed、showpoint、left）；setprecision(2) 决定实数保留两位；setw(8)、setw(20) 决定这一列占多宽。把三者叠起来，输出就是一张对齐的表。

易错

setw 只影响“下一个”输出项，写完一个就要再设一次；setprecision 与 setiosflags 则会一直生效。把三者当成同一种“一次性设置”，表格的对齐会从第二列开始错位。

12.8 综合示例：用输出格式画函数图像

讲义最后一个例子把前面所有东西拼在一起：用字符 * 在终端上画出函数 f(x) = −x² − 2x + 20 在区间 [−5, 5] 上的形状。程序先定义两个常量：NUM_COLS = 80 表示总共 80 列，FIELD_SIZE_X = 10 表示 x 值占 10 列。

变量设置是：xinit = −5、xfinal = −xinit = 5、xstep = 0.5、ystep = 2.0。先打印表头，再用 setiosflags(ios::scientific | ios::showpoint) 与 setprecision(2) 把后面的实数统一成两位小数的科学计数法；然后算出起点的函数值 yinit，作为“零高度”的基准。

for (float x = xinit; x < xfinal; x += xstep) {
    y = evaluate_function(x);
    indent = (int)((1.0 * y - yinit) / ystep + 0.5);
    cout << setw(FIELD_SIZE_X - 2) << x << " ";
    if (indent >= 0 && indent < NUM_COLS - FIELD_SIZE_X) {   // within bound
        cout << setw(indent) << "*";
        cout << setw(12) << y;
    }
    cout << endl;
}

核心是 indent 这个整数：它把函数值换算成“要空多少格才画 *”。(y − yinit) / ystep 得到以 ystep 为单位的相对高度，加 0.5 再取整相当于四舍五入，避免 2.999 被截成 2。setw(indent) 先输出 indent 个空格，再输出 *，星号就落在对应的水平位置上；后面 setw(12) 再把该点的函数值打印在同一行。

边界检查 indent >= 0 && indent < NUM_COLS − FIELD_SIZE_X 很关键：函数值超出绘图区时 indent 可能为负或过大，setw 拿到这种值会输出整行空格或直接错位，所以越界的点只打印 x 与换行。讲义给出的输出中，−5.00e+00 对应 5.00e+00，−1.00e+00 对应 2.10e+01，正好是抛物线的顶点位置。

辨析

“画图”在这里不是图形库，而是用 setw 控制空格数量，把字符摆到指定列。宽度既是排版工具，也是定位工具——这是本讲最值得带走的一个用法。

12.9 与 C 的关系及小结

讲义在备注里说明：C++ 中的大多数 I/O 与流操纵符、流函数，C 也支持，细节可以查阅 cstdlib 库。这句话的分量在于“不必把它们当成 C++ 独有”：文件打开、读字符、写字符这些操作在 C 里有对应的库函数，只是名字与调用形式不同。第 13 章讲动态内存时会看到同样的对照（new/delete 对 malloc/free）。

把整章压缩成一条主线：文件是永久的字节集合，流是访问它的统一接口；打开建立连接，关闭断开连接；>> 与 << 负责带类型转换的批量读写，get 与 put 负责逐字符的精确读写，fail 与 eof 负责查询状态；标志决定格式，操纵符修改标志。这五件事按顺序记住，读写任何文本文件都不会乱。

考点

一段完整的文件程序必须能回答四个问题：用哪个流类型？对哪个文件 open？用 >>/get 读还是用 <</put 写？什么时候 close、关闭前有没有检查 eof 或 fail？
